rkt-pythonize
=============
A Racket-hosted DSL that compiles to Python.

A module written in `#lang rkt-pythonize` *is* a Python program.  The language
expands the module body at compile time, compiles it to Python, and the module
exports the result as the string `python-code`; the command line tool only
writes that string out.  Version 2.0.0.

Quick start
-----------

`fact.rkt`:

```racket
#lang rkt-pythonize
(define (fact n) (if (= n 0) 1 (* n (fact (- n 1)))))
(print (fact 5))
```

```
$ raco rkt-pythonize fact.rkt      # writes fact.py; -o - writes to stdout
$ python3 fact.py
120
```

The Python it writes:

```python
# generated by rkt-pythonize
def fact(n):
    return (1 if (n == 0) is not False else (n * fact((n - 1))))

print(fact(5))
```

The language
-------------

* `racket/base` is re-exported as it is, so `define`, `lambda`, `if`, `begin`,
  `set!`, `quote` and `define-syntax` are Racket's: a macro written with
  `define-syntax-rule` is an ordinary Racket macro, and hygiene is Racket's.
* What this language adds has an `lb:` prefix: `lb:raise`, `lb:trampoline` and
  `lb:with-handler`.
* Only `#f` is false.  An `if` compiles to `(then if test is not False else
  else)`, so `0`, `""`, `'()` and `None` are true, as they are in Racket.
* A free identifier is a Python global: `(print (len "abc"))` becomes
  `print(len("abc"))`.  Names are munged into readable Python identifiers --
  `even?` is `even_p`, `set-car!` is `set_car_b`, `object-ref` is `object_ref` --
  and a name that is a Python keyword gets a trailing `_`.
* `+ - * / quotient modulo expt = < > <= >= equal? eq?` become Python's own
  operators, and `not` becomes Python's `not`.
* `quote` is data: integers, floats, strings, booleans, lists (which are Python
  lists) and dicts whose keys are strings.  There is no symbol type, so quoting
  a symbol is a compile error, and there is no `eval` and no `gensym`.
* `require` and `provide` compile to nothing: they are about the Racket module,
  not about the Python program.  A required library's *macros* work when their
  expansion is compilable; its procedures are Racket procedures and are not
  available to the Python program.

Statements and expressions
--------------------------

An `if` or a `begin` in statement position becomes a Python statement, so its
branches can hold `set!` and other statements.  The same forms in an expression
position become a Python conditional expression and a call to `_begin`.  This is
what makes Racket's own control forms work:

```racket
#lang rkt-pythonize
(define x 0)
(when #t (set! x 5))            ; when and unless end in (void), which is None
(unless #f (set! x (+ x 1)))
(if (> x 5) (set! x (* x 2)) (set! x 0))
(print (cond [(= x 12) "twelve"] [else "other"]))
(print (and #t x))
```

`let`, `let*`, `or` and `case` are not compilable (they expand to `lambda`s or
to `let-values` with bindings), a `lambda` is only a definition's value, and
`set!` of an unbound name is a Racket error.  Racket library *procedures* such
as `third` are not provided either; they would be Python globals and fail as
`NameError`s unless the Python program defines them.

The `lb:` forms
---------------

```racket
(lb:raise e)              raise e; it arrives as a Python exception
(lb:with-handler h e)     run e with h handling what it raises
(lb:trampoline e)         call what e returns while it is a procedure
```

`lb:with-handler` runs the body where it stands, so a value position guards it:

```racket
(define (recover e) (+ e 1))
(print (lb:with-handler recover (lb:raise 41)))          ; 42
(print (if #f (lb:with-handler recover (lb:raise 1)) 7)) ; 7
```

Tail calls are explicit.  `lb:trampoline` calls the value of its body and keeps
calling while that value is a procedure, so a body that ends in a tail call
returns a 0-arity procedure and loops, and a body that returns anything else is
done:

```racket
(define (count n acc)
  (lb:trampoline (if (= n 0) acc (count (- n 1) (+ acc 1)))))
(print (count 100000 0))                                 ; 100000, flat
```

A procedure that drives `lb:trampoline` is emitted twice -- `f` drives and
`f_body` holds the bounces -- so a bounce never re-enters a driver.

Runtime pieces
--------------

The generated program carries only the pieces it uses, each one named after the
form or the procedure that asked for it:

| source | Python |
| --- | --- |
| `(lb:raise e)` | `_raise`, `_Raised` |
| `(lb:trampoline e)` | `_trampoline` |
| `(lb:with-handler h e)` | `_with_handler` |
| `begin` in an expression | `_begin` |
| `(list 1 2)` | `list` (a Python list, as a quoted list already is) |
| `(apply f xs)` | `apply` |
| `(keyword-apply f kw xs)` | `keyword_apply` |
| `(object-ref xs 0)` | `object_ref` |
| `(object-set! xs 0 1)` | `object_set_b` |
| `(object-get-attr xs "append")` | `object_get_attr` |
| `(object-set-attr! xs "a" 1)` | `object_set_attr_b` |
| `(object-has-attr? xs "append")` | `object_has_attr_p` |
| `(void)` | `None` |

Command line
------------

```
$ raco rkt-pythonize [-o <output>] <module.rkt>
```

`<module.rkt>` becomes `<module>.py`.  With `-o -` the Python goes to standard
output, and with `-o <output>` to that file.  Before the package is installed,
the same entry point runs as `racket cli.rkt [-o <output>] <module.rkt>`.

The Python is a value as well: requiring the module gives `python-code`:

```racket
> (require (file "fact.rkt"))
> (display python-code)
```

Tests
-----

```
$ TMPDIR="$PWD/.tmp" raco test tests/
```

The end-to-end tests compile a `#lang rkt-pythonize` module in a subprocess and
run the generated program with `python3`.  The subprocess gets a `PLTCOLLECTS`
that points at this checkout, so the checkout wins over an installed copy of the
package.

Layout
------

```
main.rkt                     the language: racket/base plus the lb: forms
lang/reader.rkt              how #lang rkt-pythonize finds it
core/compile.rkt             expanded syntax -> Python source (phase 1)
cli.rkt                      raco rkt-pythonize, and the launcher
tests/dsl.rkt                end-to-end tests
scribblings/rkt-pythonize.scrbl  the manual
```

Design notes
------------

* Clojure is the inspiration for the shape of the compiler, not for the syntax:
  one small compiler instead of a pipeline of passes, no CPS, and generated
  Python that stays readable.
* Macros are Racket's, so they run at compile time and need no runtime support:
  the expander has already run when the compiler sees the body.
* There is no separate `core.py` and no runtime library beyond the pieces above.
* `raco setup rkt-pythonize` builds the manual.
